# Poster Production Pipeline

## Status

Deterministic static-production pipeline for AI Creative OS with direct Gemini image generation.

The campaign generator remains responsible for strategy, safe copy, image direction and deterministic overlay data. The poster pipeline converts an accepted campaign into a PNG without allowing an image model to render customer-facing factual text.

## Flow

```text
Verified campaign request
  ↓
Gemini campaign generation
  ↓
Accepted creative JSON
  ├─ imageGeneration (NO_TEXT_OR_LOGOS)
  └─ overlaySpec (headline / price / CTA)
       ↓
GeminiImageProvider OR local base image
       ↓
Text-free base image
       ↓
Deterministic HTML/CSS template
       ↓
Headless Chrome screenshot
       ↓
Final PNG
       ↓
PNG dimension + file sanity QA
       ↓
manifest.json
```

## Gemini image ladder

- draft: `gemini-3.1-flash-lite-image` — Nano Banana 2 Lite
- production: `gemini-3.1-flash-image` — Nano Banana 2
- premium: `gemini-3-pro-image` — Nano Banana Pro

`GeminiImageProvider` uses the Gemini Interactions API and returns inline base64 image data. `producePoster()` persists that image and never requires a third-party image host.

The poster demo deliberately uses the **draft** role. Production and premium roles are available to application code but should pass the escalation guards in `src/providers/geminiPolicy.ts`.

## Spend guard

Billing access does not automatically authorize media spending.

To let the poster demo call Nano Banana 2 Lite:

```bash
export ALLOW_PAID_MEDIA=true
unset POSTER_BASE_IMAGE_PATH
npm run poster:demo
```

To avoid image-generation cost entirely, supply an existing image:

```bash
export POSTER_BASE_IMAGE_PATH="/absolute/path/to/base-image.jpg"
npm run poster:demo
```

## Deterministic rendering

The poster renderer deliberately does not use proposed brand identity unless it has been approved.

Critical customer-facing text remains outside the generated base image. The accepted campaign's `overlaySpec` supplies the final text, and `overlaySpec.price.display` is generated by application code rather than an image model.

The image prompt always reinforces:

- no promotional copy
- no prices or numbers
- no logos or app icons
- no badges or labels
- no watermarks

## Local renderer

A local Chrome/Chromium executable is used in headless mode to render the HTML into an exact-size PNG.

On macOS the renderer automatically checks standard Google Chrome and Chromium application paths. Set `CHROME_PATH` only when Chrome lives elsewhere.

## Environment

```bash
GEMINI_API_KEY=...
GEMINI_CAMPAIGN_MODEL=gemini-3.5-flash-lite
GEMINI_IMAGE_DRAFT_MODEL=gemini-3.1-flash-lite-image
GEMINI_IMAGE_RESOLUTION=1K
ALLOW_PAID_MEDIA=false
POSTER_BASE_IMAGE_PATH=

# Optional renderer override
CHROME_PATH=
```

Never commit API keys.

## Live demo

```bash
npm run poster:demo
```

Default output:

```text
outputs/T001-AI-DEMO-001/
├── base-image.jpg
├── poster.html
├── poster.png
└── manifest.json
```

When Gemini generates the base image, the manifest records model, request ID, usage metadata and estimated image output cost when available.

## QA boundaries

The deterministic QA checks:

- campaign generation passed all gates
- final HTML contains required deterministic overlay values
- logo markup is absent when logo usage is `OMIT`
- rendered output is a PNG
- PNG dimensions exactly match the campaign format
- PNG has a non-trivial file size

The next QA milestone is visual/model-assisted validation for product accuracy, safe zones, crop quality, legibility, food prominence and brand-asset similarity.
