# Poster Production Pipeline

## Status

First deterministic static-production pipeline for AI Creative OS.

The campaign generator remains responsible for strategy, safe copy, image direction and deterministic overlay data. The poster pipeline converts that accepted campaign into a real PNG without allowing an image model to render customer-facing factual text.

## Flow

```text
Verified campaign request
  ↓
Campaign Generator V3
  ↓
Accepted creative JSON
  ├─ imageGeneration (NO_TEXT_OR_LOGOS)
  └─ overlaySpec (headline / price / CTA)
       ↓
Image draft provider OR existing local image
       ↓
Text-free base image
       ↓
Deterministic HTML/CSS template
       ↓
Headless Chrome screenshot
       ↓
1080x1350 PNG
       ↓
PNG dimension + file sanity QA
       ↓
manifest.json
```

## Image provider

`GetimgImageProvider` uses getimg.ai's synchronous image endpoint directly over HTTP:

- base URL: `https://api.getimg.ai`
- endpoint: `POST /v2/images/generations`
- authentication: bearer API key
- default model: `gemini-3-1-flash-lite-image` (Nano Banana 2 Lite)
- default resolution: `1K`
- output: JPEG base image

The model/provider can be changed through environment variables without changing poster orchestration.

No getimg SDK dependency is required. The repository uses standard `fetch` so CI and the core project remain lean.

## Deterministic rendering

The poster renderer deliberately does not use the current proposed ATTHA'S identity.

Until identity approval, the template uses:

- neutral black/white layout
- system sans-serif typography
- no ATTHA'S logo
- no proposed red/gold palette
- no AI-generated headline, price, CTA, logo, badge or label inside the base image

The accepted campaign's `overlaySpec` supplies the final text. `overlaySpec.price.display` is generated by application code, not by the image model.

## Local renderer

A local Chrome/Chromium executable is used in headless mode to render the HTML into an exact-size PNG.

On macOS the renderer automatically checks the standard Google Chrome and Chromium application paths. Set `CHROME_PATH` only when Chrome lives elsewhere.

## Environment

```bash
AI_CAMPAIGN_PROVIDER=groq
GROQ_API_KEY=...
GROQ_CAMPAIGN_MODEL=openai/gpt-oss-120b

GETIMG_API_KEY=...
GETIMG_IMAGE_MODEL=gemini-3-1-flash-lite-image
GETIMG_IMAGE_RESOLUTION=1K

# Optional local-image fallback
POSTER_BASE_IMAGE_PATH=

# Optional renderer override
CHROME_PATH=
```

Never commit API keys.

## Live demo

```bash
npm run poster:demo
```

Default output:

```text
outputs/T001-AI-DEMO-001/
├── base-image.jpg
├── poster.html
├── poster.png
└── manifest.json
```

If `POSTER_BASE_IMAGE_PATH` is supplied, the pipeline skips getimg.ai and uses that file as the base image.

## QA boundaries

The initial deterministic QA checks:

- campaign generation passed all V3 gates
- final HTML contains required deterministic overlay values
- logo markup is absent when logo usage is `OMIT`
- rendered output is a PNG
- PNG dimensions exactly match the campaign format
- PNG has a non-trivial file size

Later phases should add visual/computer-vision QA for text-safe zones, crop quality, legibility, food prominence and asset similarity.
